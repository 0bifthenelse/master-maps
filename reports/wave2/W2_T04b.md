# W2-T04b exclusion accounting and validation hardening

Agent: wave2-8. Branch master. Scope: exclusion accounting module, wiring into deduplicate, refresh, validate, additive checks in qa-spatial, unit tests.

## 1. What landed

New module `scripts/data/exclusion-report.ts` (schema, reason codes, accounting sinks, artifact audit, coverage reconciliation). It owns `data/qa/exclusion-report.json`.

Report shape (per source layer, key `source::layer::kind`): `input`, `accepted`, `observedAccepted`, `mergedDeduplicated`, `clippedFragments`, `excludedByRule[{rule,count,reason}]`, `invalidGeometry`, `outsideBoundary`, `observedDelta`, `unexplained`. Plus `stages[{stage,reason,count,detail}]`, `totals`, and `invariants{balanced,unexplainedTotal,layersUnbalanced,stagesUndeclared}`.

Enforcement: `buildExclusionReport` throws `ExclusionAccountingError` when a non-canonical layer fails `input == accepted + excluded + invalidGeometry + outsideBoundary` or when `totals.unexplained != 0`. The error carries the fully built report, and the CLI writes it before exiting 1, so a failing run still leaves evidence on disk. Stage drops whose reason has no matching `excludedByRule` entry are reported in `invariants.stagesUndeclared` and surfaced by validate as warnings; they do not fail the build, because the source accounting may legitimately be produced by a different stage than the stage counter.

`DROP_REASONS` (exclusion-report.ts:365-399) is the single vocabulary shared by every writer, so a stage counter and a source rule cannot drift apart silently. `STAGES` (exclusion-report.ts:426-435) names the pipeline stages.

## 3. Wiring

`deduplicate.ts`: `deduplicateFeatures(features, accounting?)` (deduplicate.ts:400-482) classifies every merge as exact identity or metric conflation, records per source/layer/kind input, accepted and merged counts, and emits a stage drop per merge. `deduplicateAll` takes an optional `DedupAccounting` and returns it. The two existing callers in refresh and the three unit tests keep working unchanged because the parameter is optional.

`refresh.ts`: creates a `stageSink` and a `DedupAccounting`, passes the accounting to `deduplicateAll`, and writes the pipeline report to `data/qa/exclusion-report.json` after build-tiles and build-search-index so tile and search counters are present.

`validate.ts`:
- `REQUIRED_KINDS` is now boundary, building, road, water, landuse, poi, transport, place, business, address (validate.ts:20).
- `renderTileIssues` (validate.ts:133-166) asserts a `.mmt` exists for every manifest entry, that none exceeds 2 MiB, and that a 50-tile stride sample decodes with `decodeRenderTile` and carries its own tile id.
- `fictiveFlagIssues` (validate.ts:168-177) errors when a water or road record whose `sourceMetadata.fictif` is `true` lacks `fictiveAxis`.
- `validateSearch` now takes the decoded features and errors when a named canonical kind present in the tiles has no record in the search index.
- `exclusionReportIssues` (validate.ts:179-193) errors on a missing report, on `unexplained != 0`, and on any unbalanced source row; it warns on undeclared stage drops.
- `coverageIssues` plus `reconcileCoverage` compare `coverage.json` totals and per-kind counts with the counts decoded from the tiles; both are written into `validation-report.json` under `reconciliation`.
- `tileIdentityIssues` tolerates the slim manifest: when `features` is absent it only checks `featureCount` against the decoded payload and fragment identity uniqueness.

`qa-spatial.ts` (additive only): `selectStratifiedFeatures` (qa-spatial.ts:222-245) picks 50 features round-robin across 0.1 degree local-coordinate cells, so the sample spans the department rather than Auch. `buildStratifiedReport` aggregates the worst normalized and tile residuals and is written to the existing `spatial-report.json` under a new `stratified` key, with a failure when fewer than 50 samples were drawn or the worst residual exceeds 1 m. All previous checks are untouched.

## 4. Tests

`tests/unit/exclusion-report.test.ts`, 9 tests, all green. They cover the balance invariant, the unexplained failure path (asserts both the throw and that the attached report carries `unexplained = 300`), undeclared stage drops, duplicate row merging, the canonical scan, the streaming GeoJSON scanner, and coverage reconciliation in both the matching and mismatching case. One test initially failed and caught a real defect: a second `record` call with a populated `excluded` rule and no explicit `excludedCount` re-derived the count from that call's own input and accepted, which double counted. The fix is that every call site passes `excludedCount` explicitly and the umbrella rule passes 0.

`npx tsc --noEmit` is clean across the repository. `npx vitest run tests/unit/exclusion-report.test.ts tests/unit/deduplication.test.ts tests/unit/conflation.test.ts` gives 22 passed.
